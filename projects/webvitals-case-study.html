WebVitals Case Study — a slow page, made fast

A real before/after. A deliberately-bad page scores LCP 4100ms, CLS 0.28, INP 540ms. After optimization: LCP 1950ms, CLS 0.05, INP 160ms — and a 14-rule analyzer that caught 28 findings down to 1.

LCP −52% CLS −82% INP −70% 46 tests ✓ 14-rule analyzer

01. The before/after (real numbers)

LCP Largest Contentful Paint
4100ms → 1950ms (−52%)
FCP First Contentful Paint
3200ms → 1500ms (−53%)
INP Interaction to Next Paint
540ms → 160ms (−70%)
CLS Cumulative Layout Shift
0.28 → 0.05 (−82%)
BeforeAfter (bar width = relative improvement)

TTFB also dropped 1900 → 620ms (better caching, no render-blocking).

02. What the analyzer caught (28 → 1)

Before — 28 findings

  • Render-blocking CSS & JS
  • Unsized images / missing width·height
  • Layout shift from late-loading fonts
  • No preload on hero image
  • Huge unoptimized hero (no WebP/AVIF)
  • Long task blocking the main thread

After — 1 finding (passes)

  • ✅ All render-blocking resolved
  • ✅ Images responsive + format-converted
  • ✅ Fonts preloaded with font-display:swap
  • ✅ Long tasks split into chunks
  • ✅ Core Web Vitals all in the "good" band

03. Run the analyzer

Point it at any HTML and get a report. The analyzer is pure Python — no browser needed.

# deps pip install fastapi uvicorn # serve the report UI on http://127.0.0.1:8768 python3 vitals/app.py # analyze the example pages python3 -m vitals.analyzer examples/bad.html python3 -m vitals.analyzer examples/optimized.html # tests — 46 passing (rules, metrics, report) python3 -m pytest tests/ -q -p no:asyncio
